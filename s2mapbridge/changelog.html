S2MapBridge — Changelog

v2.25 2026-08-01
  • ChangedPlugin renamed from S2MapsImporter to S2MapBridge.
  • FixedAnimated prop bone assignment was scrambled: ParseANIM used AGRP bone indices directly as skeleton bone indices. Fixed by building a name-to-index map from the skeleton and translating each AGRP bone via name lookup. Rotating props (e.g. crane wheels) now animate correctly.
  • FixedLayout B multi-mesh props: incorrect BaseVertex offset caused geometry collision when multiple meshes shared one draw call buffer. Each sub-mesh now gets the correct vertex base offset.
  • FixedStatic meshes imported via plugin had CollisionTraceFlag = CTF_UseSimpleAsComplex (2) with zero simple shapes, resulting in no physics body. Physics sweep traces returned 0 hits. Fixed by removing the CTF override — meshes now use CTF_UseDefault (0), matching FBX-imported behavior.
  • Fixedblack_material_interface key was missing from load_material_assets(), causing material_assets.get() to always return None. Reflectivity meshes now correctly receive the M_BlackSimple material.
  • FixedDirectionalLight intensity of 0 (common in imported scenes) is now clamped to 0.01 lux to avoid invisible sun light.
  • AddedMisc tab with two tool groups. Fix Stucked Lights: iterates all ALight actors in the scene, sweeps each light upward with a box trace loop (up to 20 iterations), and repositions lights embedded inside static mesh geometry to the nearest surface. Uses per-iteration push direction (Start−End).GetSafeNormal() to avoid Chaos EPA non-determinism on thin meshes. Debug box drawn for 10 s. Full undo transaction. Convert Light: three icon buttons to convert selected lights to Point / Spot / Rect, preserving all shared properties (intensity, color, attenuation radius, temperature, source radius/length, falloff, IES), actor label, and outliner folder.
v2.24 2026-07-26
  • FixedMap Name field in the import UI now displays with the correct read-only style (dark background #292B2F, muted text). Added TextStyle.ColorAndOpacity to PyToolkitUI.Input.FieldReadOnly — previously only ForegroundColor was set, which does not affect SEditableText rendering.
  • FixedMBUF secondary VB (split-format props where VB[0] = POSITION, VB[1] = TEXCOORD+NORMAL) with element count mismatch now applies secondary data to min(VB.ElementCount, LastPosVBCount) vertices instead of skipping entirely. Prevents UV=0 and wrong normals on partial count-mismatch cases.
  • ImprovedMBUF secondary VB skip warning messages now individually report the reason: no secondary attributes found / no prior POSITION VB / element count mismatch (with actual counts). Easier diagnosis in Output Log.
  • FixedPhys Material assignment restored (set_physicsurface was accidentally commented out). Physical surface type is now assigned when placing static mesh actors.
  • FixedSkeletalMesh builder: added bounds checks for both MeshData.Indices[IdxPos] (IdxPos out of range) and MeshData.Vertices[GVIdx] (GVIdx out of range). Degenerate draw calls are now skipped with a warning instead of crashing.
  • FixedAsset name sanitization: spaces in vmdl_c base filename (e.g. willow branch) replaced with underscores to satisfy UE PackageName requirements.
  • AddedCheckpoint save every 100 imported assets: SaveDirtyPackages + _imported.json write. Protects against crash data loss on large maps.
  • FixedAutoResolveMapName: added LastResolvedVpkPath dedup cache to prevent double-fire (file picker + text change both trigger OnTextChanged). Fixed pipe: child process no longer receives parent's stdout read handle as stdin.
  • FixedMaterial pipeline: replaced Fancy Blend Mode 0/1/2/3 static switches with scalar Fancy Blending parameter (F_FANCY_BLENDING), and Detail Texture 1/2 bools with scalar Detail Texture (0–2). Matches CS2 shader enum semantics.
  • Fixedset_param_checked no longer raises on real param collision for layer_name_1 and similar multi-layer keys — silently overwrites when previous value is empty string (KV3 last-wins semantics).
  • FixedExploded geometry on MBUF meshes with non-consecutive VB indices (e.g. VB[0]/VB[2]/VB[4] in n0_lr0_c2_s_cb_mesh). Root cause: VBVertOffsets[Sub.VBIndex] used VBIndex as array ordinal — draw8 (VBIndex=2) got cumulative offset 763 instead of correct 627, producing OOB indices. Fixed by replacing TArray<int32> VBVertOffsets with TMap<int32,int32> VBIndexToOffset keyed by actual MBUF vi, built with new OutPerVBVIIndices output parameter tracking which MBUF VB array index each position VB corresponds to. Added IB pre-scan to derive authoritative per-VB vertex counts from max raw IB index when CS2 under-reports m_nElementCount for meshopt-compressed VBs.
v2.23 2026-07-24
  • FixedWorkshop / community maps: resource references in m_material and m_materialGroups use a HEXID  path format (16-char content hash + double space). The hash prefix is now stripped before storing material paths, so materials like officewindowparallax are correctly exported to _materials.json.
  • FixedPaths with spaces (e.g. office interior/officewindowparallax) in decompiler output lines now parsed correctly using split("] ", 1) instead of split(" ")[-1], which truncated to the last token.
  • FixedTexture UE asset paths sanitized with to_valid_filename() at construction time — eliminates "Can't convert path … too many spaces" errors for workshop map textures.
  • FixedMaterial dictionary lookup in Phase 3 now uses sanitized keys, matching the sanitized names produced by find_material(). Previously, space-in-path materials were found in _materials.json but silently missed in the UE lookup.
  • FixedPer-drawcall actors with more materials than mesh slots (e.g. painting_portrait01_draw0) now pick the correct material using the stored drawcall_index instead of falling through to the wrong slot.
v2.22 2026-07-23
  • FixedCanvas / picture meshes (e.g. picture_01) displayed the frame material instead of the canvas image. Root cause: skin material matching used the current skin's index reference instead of the default skin. Fix: match slot name against the default skin's basename list to get a stable index, then apply that index into the current skin.
  • FixedCommunity VPK decompile phase emitted a SlowTask overflow warning — ScopedSlowTask total was 1.0 but 7 progress frames (one per extension) were entered. Total corrected to 7.0.
  • FixedParam collision exception when a settings key was set twice with the same effective value but an empty-string initial state. Empty string is now treated as "unset" and silently overwritten.
  • AddedVPK selection now warns when a non-_dir.vpk file is chosen and a _dir.vpk variant exists in the same folder.
  • AddedProgress spinner shown while the map name is resolved from the selected VPK (blocks main thread during CLI call).
  • ChangedMap Name field made read-only — displays auto-detected name with a placeholder when empty.
  • ChangedBoundsScale = 50 applied to all skeletal mesh components on spawn, eliminating LOD pop-in on animated props visible at range.
  • ChangedImport log cleaned up: removed per-texture, per-material-param, per-entity-instance, and sky-mesh noise lines. Near-duplicate light skips now include the entity ID.
v2.21
  • AddedPhase 2 now automatically saves all imported asset packages after the import loop finishes (SaveDirtyPackages).
  • AddedOverlay render order (m_nOverlayRenderOrder) propagated from worldnode data to TranslucencySortPriority on spawned overlay actors.
  • FixedCable slack mapping: cables with moderate slack values were sagging through the ground due to the cap threshold being too high. Cap lowered from 130 % to 102 % of chord distance.
  • FixedProgress bar name no longer jumps when a filename exceeds 32 characters — truncated with … suffix.
  • FixedPhase 2 progress bar label corrected from Decompiling models to Importing models.
  • FixedMaterials with csgo_vertexlitgeneric + F_DECAL_TEXTURE: 1 were incorrectly routed to the decal material instance. They now use the standard csgo_vertexlitgeneric path.
v2.20
  • FixedSkeletalMesh props with more than one material slot had all geometry assigned to slot 0. Root cause: FSkeletalMeshImportData::Materials was not populated, so UE reordered render sections freely. Fixed by populating MaterialImportName and ImportedMaterialSlotName for each section.
  • FixedMDAT draw-call parser rewritten to use brace-depth flushing instead of m_nStartIndex-triggered flushing. Fixes incorrect BaseVertex assignment on meshes where KV3 field order differs from the expected sequence.
  • FixedDouble-flush bug: after the brace-depth flush, the end-of-file safety net re-added the same draw call, producing a spurious third material slot. Fixed by clearing Current immediately after flushing inside the } handler.
  • FixedMVTX-at-vbib_block: stale blocks-cache entries with old decompiler format (MBUF block index) were misrouted to MVTX data, producing geometry garbage. Plugin now detects the mismatch, resets the index, and falls back to a fresh CLI run.
v2.17
  • FixedCS2 omits blend weight / blend index data for props bound to a single bone. The plugin now synthesises implicit skinning (bone 0, weight 1.0) for these props so they import correctly as SkeletalMesh assets.
v2.16
  • AddedFull animated prop pipeline: CS2 animated props are imported as USkeletalMesh + USkeleton + UAnimSequence from embedded ANIM / ASEQ / AGRP blocks.
  • AddedZSTD v1.5.6 vendored into Source/ThirdParty/Zstd/. Required for stride-4 secondary vertex buffers that store compressed vertex-color data.
  • FixedUV1 format 16 (R32G32_FLOAT) was decoded with the wrong branch constant (was 2, should be 16). Affected UVs on worldnode meshes with a secondary vertex buffer.
  • FixedPrimary MVTX decoder lacked handling for UV0 formats 37 (R16G16_SNORM) and 16 (R32G32_FLOAT). Both added, matching VRF reference decode (shorts / 32767.0f).
  • FixedTangent decode added for vertex attribute format 42 (R8G8B8A8_SNORM). Eliminates "nearly-zero tangent" import warnings; bRecomputeTangents set to false.
  • FixedStride-4 secondary vertex buffer meshopt decode: CS2 sets m_bMeshoptCompressed = true but stores raw bytes. Plugin now checks for the 0xA0 magic byte before calling meshopt, falling back to memcpy.
  • FixedMoveTemp bug on cached draw-call lists caused 26 import failures on de_cache. Fixed — all 933/933 imported.
v2.9
  • FixedZSTD false-positive warning: m_bCompressedZSTD = true in the VB section (not the IB section) incorrectly triggered an error log. Log now gated inside if (bInIndexSection).
  • FixedSpurious m_nVertexCount boundary warning removed — the count refers to unique vertices per draw call, not the cluster size; boundary-shared vertices caused false positives across every full-map import.
  • ChangedRemoved all investigation-era verbose diagnostic logs (position dumps, raw-index dumps, per-submesh KV3 logs). Kept summary logs and all Error/Warning guards.
v2.8
  • FixedBaseVertex off-by-one: KV3 field order in MDAT places m_nBaseVertex / m_nVertexCount before m_nStartIndex. Old parser flushed on m_nStartIndex, so every draw call received the next cluster's BaseVertex — causing stretched / spiked polygons on all worldnode meshes. Fixed with a pending-buffer that defers BaseVertex until the next draw call boundary.
  • FixedIB→VB mapping now derived from parsed draw call fields (m_indexBuffer.m_hBuffer, m_vertexBuffers[0].m_hBuffer) instead of a heuristic group-detection algorithm.
  • FixedMultiple IBs in m_indexBuffers = [{…},{…}] (multi-material): only the last IB was flushed. Added flush-on-new-brace inside the IB section of ParseCTRL.
  • FixedMBUF multi-material VertOffset: when IBCount > VBCount, extra IBs used a wrong cumulative vertex offset. Fixed by clamping the VB index to min(ii, VBCount-1).
v2.6
  • AddedBatch CLI mode (RunCLIBatch): runs the S2V decompiler once with -i <tempdir> -a instead of once per file. 3.2× faster — de_overpass 939 meshes: 94 s vs 297 s.
v2.5
  • FixedMulti-embedded-mesh worldnode support: all vertex buffers are now concatenated, index buffers supplemented from binary data, and startIndex fixup applied via draw-call group detection. Eliminates missing geometry on complex worldnodes.
v2.2
  • AddedFull binary parsing pipeline for CS2 .vmdl_c files — vertex layout decode, MVTX / MBUF path, tint colour grouping, and multi-material section support.
  • AddedStatic mesh import (UStaticMesh) via FMeshDescription + FPolygonGroupID — preserves material section order inherently.
  • AddedTint colour per-submesh grouping: worldnode meshes with per-instance tint are split into separate UE assets by colour group.
